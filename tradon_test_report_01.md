# Tradon — отчёт по тестовому запуску №1

**Окружение:** Windows, Docker (PostgreSQL), CLI
**Статус:** Первый рабочий запуск, ядро генерирует сигналы

## 1. Результат — успешно ✅

Сигналы отработали корректно, совпали с ожиданиями при ручной проверке ("удачно попали" при тестировании).
Это подтверждает, что связка Data Layer → Strategy Engine → Signal Engine работает по задуманной архитектуре (раздел 3 концепции).

---

## 2. Проблема: однократный запуск вместо мониторинга

**Что наблюдается:**
Команда CLI выполняется один раз (получает данные → считает сигнал → завершает работу). Чтобы получить новый сигнал, нужно запускать команду вручную заново.

**Ожидаемое поведение:**
Бот должен работать в режиме непрерывного мониторинга — сам, с заданным интервалом, опрашивать источник данных (iTick) и генерировать сигналы, без ручного перезапуска.

**Вероятная причина:**
В MVP реализован только однократный проход (`get_ohlcv()` → расчёт → вывод), а компонент **Task Scheduler / Async Engine** (раздел 3.6 концепции) — цикл опроса с интервалом или подписка на WebSocket-поток — ещё не подключён к CLI.

**Что нужно сделать:**
- Добавить в CLI режим "run" с циклом (`while True` + `asyncio.sleep(interval)` для REST-опроса, либо постоянное WebSocket-соединение для реал-тайма).
- Вынести интервал опроса в конфиг (YAML/ENV), а не хардкодить.
- Предусмотреть корректную остановку (Ctrl+C → graceful shutdown, закрытие соединений с БД и WebSocket).

**Приоритет:** Высокий — без этого CLI непригоден даже для базового тестирования сигналов в динамике.

---

## 3. Проблема: нет выбора валютной пары

**Что наблюдается:**
Нет возможности указать, по какой валютной паре проводить анализ/мониторинг — пара, судя по всему, зафиксирована в коде.

**Ожидаемое поведение:**
Пользователь должен иметь возможность указать одну или несколько пар при запуске (например, через аргумент командной строки), не редактируя код.

**Вероятная причина:**
В MVP список инструментов не вынесен в параметры запуска/конфиг — вероятно, захардкожен в `iTickProvider` или в точке входа CLI.

**Что нужно сделать:**
- Добавить CLI-параметр, например: `tradon run --symbols EURUSD,GBPUSD` (через `Typer`, как заложено в стеке).
- Либо/дополнительно — список пар по умолчанию в конфиг-файле (YAML), с возможностью переопределить через CLI-флаг.
- Провалидировать, что запрошенная пара поддерживается источником данных (iTick), с понятной ошибкой, если нет.

**Приоритет:** Высокий — блокирует полноценное тестирование разных пар.
